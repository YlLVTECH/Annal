# AGENTS.md

Tauri 2 desktop note app: Rust backend (`src-tauri/`) + vanilla TypeScript frontend (`src/`, no framework). UI strings and code comments are in Chinese — keep it that way.

## Commands

- `npm run tauri dev` — dev mode (requires Rust toolchain). Vite pinned to port 1420 (`strictPort:true`) in `vite.config.ts:33`; plain `npm run dev` serves frontend without Tauri APIs. HMR on `host:1421` when `TAURI_DEV_HOST` is set.
- `npm run build` — `tsc && vite build`; `tsc` is the only typecheck. No lint script, no test framework, no CI — verify with `npx tsc --noEmit` + manual dev run. Frontend Rust-style unit tests live in `src-tauri/src/lib.rs:1784` (`cargo test`).
- `npm run tauri build` — release bundle; installer at `src-tauri/target/release/bundle/nsis/Annal_<ver>_x64-setup.exe` (name follows `productName`). Release profile `src-tauri/Cargo.toml:22` uses `lto=true` + `strip=true`. NSIS hooks live in `src-tauri/windows/installer-hooks.nsh` (wired via `installerHooks` in `tauri.conf.json`): POSTINSTALL runs `SHChangeNotify(SHCNE_ASSOCCHANGED)` + `ie4uinit -show` so a changed app icon takes effect right after reinstall without a manual icon-cache flush; POSTUNINSTALL notifies so removed associations refresh immediately.
- Version single source is `package.json`; `scripts/sync-version.mjs` syncs it into `package-lock.json` / `src-tauri/tauri.conf.json` / `Cargo.toml` / `Cargo.lock` — never hand-edit those four. Bump via `npm version patch|minor|major` on a clean worktree: the `preversion` hook checks sync, the `version` hook re-syncs and stages the Tauri manifests into the auto-created version commit; push with `--follow-tags` so tag `v*` triggers `.github/workflows/release.yml` (tauri-action builds the NSIS exe and publishes the GitHub Release; the workflow re-runs `sync-version.mjs --check`, rejects a tag that disagrees with `package.json`, and replaces the auto body with `scripts/changelog-notes.mjs`'s CHANGELOG section). The settings page shows `v${__APP_VERSION__}` injected by the Vite `define` in `vite.config.ts` (declared in `src/vite-env.d.ts`) — never hardcode a version string; `CHANGELOG.md` tracks release notes.

## Architecture

- `index.html` holds the entire UI skeleton (custom titlebar, sidebar with tabs/pagination/batch-bar/search, outline pane, editor header/toolbar/table-popover, overlays). Frontend logic is modular in `src/` (no framework). `main.ts:1` is a 5-line entrypoint; `app/bootstrap.ts:51` is the composition root and small coordinators live under `src/app/` (`save.ts`, `notes.ts`, `fileSync.ts`, `settings.ts`, `window.ts`, `contextMenu.ts`, `theme.ts`).
- Global application state uses explicit signals in `state.ts:13` (implementation in `signal.ts:16`). Consumers subscribe and update UI instead of mutation sites manually calling render. Collection signals use immutable replacement semantics (new Array/Set). Low-frequency lifecycle notifications use the typed `events.ts:6` bus (`AppEventMap`).
- The editing pipeline has a synchronous one-way hot path assembled in `pipeline.ts` (`initPipeline`): `editor.ts` `onDocEdited` callback → `markdownModel.applyEdit` → debounced `outline.refreshOutline` (200ms) / `save.notifyDocumentEdited`. Do not route per-keystroke work through the generic event bus (measured +40~77% regression in `benchmark/PERFORMANCE.md:42`), and do not add direct editor↔model imports that bypass this flow. There is no split/preview view mode anymore — 即时渲染（`liveRender.ts`）直接在编辑器内呈现版式；历史弹层复用 `renderMarkdownWhole` + `.markdown-body` 样式。
- `editor.ts` owns CodeMirror 6 (`EditorView`, `StateField` for heading flash, `Compartment` for placeholder/lineNumbers/liveRender). `markdownModel.ts:1` owns the block model + `marked`/`DOMPurify` + lazy `highlight.js`（块 html 渲染目前仅剩历史弹层消费，仍随编辑增量更新）. `src/styles.css` defines light/dark themes via `data-theme`, plus `data-font-family` / `data-content-density` / `--editor-font-size`.
- `vite.config.ts:50` manualChunks: `codemirror`, `markdown` (`marked`+`dompurify`), `diff`. `highlight.js` is dynamic-imported on first code block entering viewport (`markdownModel.ts:675`).
- All backend commands are in `src-tauri/src/lib.rs:698` (via `tauri::generate_handler!` at `lib.rs:1739`), invoked from frontend via `invoke(...)`; `main.rs:5` only calls `annal_lib::run()`.
- Frontend modules of note:
  - State/signals: `state.ts`/`signal.ts` (`coalesceByMicrotask` for list render), `events.ts` (`doc:loaded`/`doc:closed`/`app:locale`)
  - Edit pipeline: `pipeline.ts`, `markdownModel.ts` (`DocText` slice interface, `applyEdit` single-block fast path vs block-level splice vs full re-parse), `editor.ts`, `liveRender.ts` (即时渲染：Lezer 语法树驱动的视口级装饰器，光标触及节点时回退源码显示，隐藏符号注册为 atomicRanges；只读文档与选区，不触碰块模型。表格等块级替换装饰**不能由 ViewPlugin 提供**——`@codemirror/view` 只允许 state field / 静态 facet 值携带块装饰，插件（函数型装饰源）会抛 `RangeError: Block decorations may not be specified via plugins`，因此走 `LiveRenderTables` 插件算视口区间 → `setTableDecos` effect → `tableDecoField`（`EditorView.decorations.from`）这条链路，effect 在微任务里派发以避免 update 期间再 dispatch)
  - UI: `sidebar.ts` (notes/files groups, pagination `listPage`/`listPageSize`, search debounce 300ms, multi-select `selectedIds`/`rangeAnchorId`, inline rename `startRename`, batch bar), `outline.ts` (heading extraction from blocks, click-to-jump, active highlight), `table.ts` (8×10 grid + smart `detectTableData` for CSV/TSV/MD), `findReplace.ts` (CM `findReplaceExtension`), `shortcuts.ts` (customizable shortcut registry: `CommandId`/`Binding`, defaults `DEFAULT_BINDINGS`, persistence via `getBindings`/`setBindings`/`resetAllBindings`, capture-phase Escape layered-exit stays non-bindable), `shortcutSettings.ts` (settings → 快捷键 page: chip UI, keydown recording, conflict detection via `findBindingConflict`, per-command `MAX_BINDINGS_PER_COMMAND`=3, `HINT_TARGETS` keeps 标题栏/工具栏 tooltips in sync with current bindings), `history.ts` (commit/restore overlay, diff via `diff` npm package), `dialogs.ts` (confirm/commit/contextMenu/settings), `i18n.ts` with `src/i18n/{zh-CN,en-US}.json` (唯一主本；`public/i18n/` 由 `vite.config.ts` 的 `syncI18nAssets` 插件在 dev/build 启动时自动同步，勿手改；`applyI18nToDocument` 支持 `data-i18n`/`-title`/`-placeholder`/`-aria`/`-args`)
  - Utils/types: `types.ts` (`NoteMeta`/`NoteVersion`/`Source`/`ContentDensity`), `utils.ts` (`MD_EXT_RE`/`IMAGE_EXT_RE`, `LIST_PAGE_SIZE=10`, `SIDEBAR_*`)

## Data model & storage

- Each note is a standalone `.md` file at a user-chosen path (via save dialog); `index.json` in the app-data dir holds metadata only (camelCase via `serde(rename_all)` at `lib.rs:78`). **Deleting a note deletes the on-disk .md file** (`lib.rs:999` + `versions` cleanup).
- `attachments/` (`lib.rs:48`) stores pasted/dropped images via `save_pasted_image` (`lib.rs:1656`); filenames deduped as `name (n).ext`. Images inserted as `![name](path)`.
- **Deleting a note deletes the on-disk .md file + its versions directory.** External files opened via dialog/drag-drop/file-association are read via `open_md_file` and written in place via `save_md_file`, never entering the note index (and never versioned). `save_file_as_note` copies an external file to a new path and registers it.
- Notes whose `.md` file was deleted externally are intentionally kept in the index so editing recreates the file — do not filter them in `load_index` (`lib.rs:637`).

## Hot path & performance details

- Keystroke hot path is incremental (no O(full-document) work per key): `editor.ts:216` feeds the model a CodeMirror `Text` (row/range slicing via `DocText:18`), `markdownModel.ts:375` `applyEdit` uses a single-block fast path (no newline + non-structural line + `simple` type), a block-level splice re-parse for newline edits (window ±1 block, verify edge blocks byte-identical, fall back to full re-parse), and line-number shifting for everything after. Word count is maintained incrementally per transaction (`editor.ts:347` `adjustCountStats` + 250ms debounce render).
- `update_note` (autosave) writes the note file but only marks the index dirty (`AppState.index_dirty:155`); `index.json` is flushed lazily (1s debounce `INDEX_FLUSH_DEBOUNCE_MS:665` + on blur/pagehide/close via `flush_index`/`close_ready`). Structural commands (`create_note`/`delete_note`/`delete_selected_notes`/`rename_note`/`restore_note_version`/`save_file_as_note`/`toggle_pin`) flush eagerly via `save_index`.
- Save coordinator `app/save.ts:121` adaptive delay: base `autosaveDelay` (300/500/1000/2000ms from settings) × factor from recent input gaps (avg <200ms →×4, <600ms →×2, >2000ms →×0.5, clamped 300–4000ms). Writes are strictly serial via `saveTail:15`; `editRevision` guards stale callbacks.
- `search_notes` (`lib.rs:767`) caches note contents keyed by `(path lowercase, mtime, size)` (`SearchCache:163`, 32MB cap `SEARCH_CACHE_MAX_BYTES:177`) and matches case-insensitively via `bytes_eq_ignore_ascii_case` without allocating per-file lowercase copies. Sidebar debounces 300ms and merges `query` vs `searchResults` signals.
- External file change detection is event-driven: a `notify` watcher on note directories (`WATCHER:150`, `watch_note_dirs:1636`) emits `fs-notes-changed`; the frontend `fileSync.ts:93` reacts (suppressing self-save events within 1500ms of `getLastLocalSaveAt`) instead of a 3s poll; a 60s fallback poll `fileSync.ts:97` + `visibilitychange` remains. Paths diffed via `find_note_relocations` (content-hash match in same dir) and merged via `sync_fs_state` (`lib.rs:1559`, returns `FsSyncResult:1551` with `changed` + `exists`).
- `highlight.js` is loaded lazily (`markdownModel.ts:675` dynamic import `highlight.js/lib/common`) the first time a code block enters the viewport; `diff` package likewise for history compare.

## Version history (git-like, linear)

- Commit records `<app_data>/versions/<noteId>/v<seq>-<ts>-<hash>.md` (empty pointer files, metadata in filename, `parse_version_file_name:261`) with commit messages in `history.json` and per-version titles in `titles.json`. Content is content-addressed in `blobs/<hash>` — identical content shares one blob (like git objects); blobs ≥4KB (`BLOB_COMPRESS_MIN_BYTES:301`) are zlib-compressed as `blobs/<hash>.z` (fast level) with original sizes in `blob-sizes.json` (fallback to plain if compression doesn't shrink). Legacy versions that stored content inline in the record file are still read (`read_version_in:447` fallback to file content).
- Versions are created only on explicit commit (`commit_note:1072`, via 提交 button / context menu), never on autosave (`update_note`); committing content+title identical to latest is a no-op (`commit_in:472`). `restore_note_version` (`lib.rs:1204`) restores any version by overwriting the note file and syncing title via `resolve_note_target` (git checkout semantics — no new version created, commit afterwards to keep it). Cleaned up with the note (`delete_note:1017`).
- The history overlay offers a 对比 mode (line diff via `diff` npm package, frontend-only) comparing the selected version against a selectable source defaulting to the latest, and hides 恢复此版本 when the latest is selected.

## Naming & paths

- **笔记名 = 文件名** — `sanitize_file_stem` (`lib.rs:505`) cleans illegal chars, collapses spaces, guards Windows reserved names (`CON`/`PRN`/… → `_` prefix). `resolve_note_target` (`lib.rs:558`) ensures note-title and file-path uniqueness (case-insensitive, auto-suffix ` (n)`), never overwriting.

## Runtime gotchas

- Window close is intercepted (`prevent_close` + `app-close-request` event `lib.rs:1770`): frontend `app/window.ts:44` flushes pending debounced saves via `flushSave` + `invoke("flush_index")`, then `invoke("close_ready")` to destroy; a 2s fallback force-destroys. Any new close-time work must fit this handshake. `closing` signal (`state.ts:26`) guards re-entry.
- File association / second instance: CLI args filtered to `.md/.markdown/.txt` via `filter_md_args:225` and relayed via `single-instance` plugin `lib.rs:1690` as `open-md-files` event and `pending_open_files` command. Frontend polls pending files on startup because the event can fire before listeners register (`bootstrap.ts:137`).
- `withGlobalTauri: false` (`tauri.conf.json:9`) — always `import { invoke } from "@tauri-apps/api/core"`; there is no `window.__TAURI__`. `convertFileSrc` for `asset:` images relies on `csp: null` + `assetProtocol.scope ["**"]`.
- API permissions are gated in `src-tauri/capabilities/default.json:6`; adding a plugin or new core API requires a permission entry there (currently `core:window:*`, `dialog:allow-open/save`).
- `open_external` on Windows must use `rundll32 url.dll,FileProtocolHandler` (`lib.rs:1244`) — `cmd /C start` mangles quoted URLs.
- Custom titlebar (`decorations: false` `tauri.conf.json:23`); `.md` file drops arrive via `getCurrentWindow().onDragDropEvent` (`bootstrap.ts:133`).
- UI state persists under `annal:*` localStorage keys: `annal:content-density` (standard/sparse/compact), `annal:font-size`, `annal:font-family` (serif/sans), `annal:sidebar-width`, `annal:sidebar` (hidden/shown), `annal:theme` + `annal:theme-mode` (system/light/dark), `annal:line-numbers`, `annal:live-render` (即时渲染开关，默认开), `annal:autosave` + `annal:autosave-delay`, `annal:list-page-size`, `annal:table-opts`, `annal:outline`, `annal:locale`, `annal:settings-category`, `annal:shortcuts` (custom shortcut bindings JSON: `Record<CommandId, Binding[]>`, defaults used when key missing/corrupt). Focus mode was removed — do not reintroduce its key. 视图模式（编辑/分屏/预览）已随即时渲染移除 — 不要恢复 `annal:view` / `annal:split-ratio` 键。
- Paste handling (`editor.ts:682`): URL over selection → Markdown link; image items → `save_pasted_image` → `![name](path)` insertion.
