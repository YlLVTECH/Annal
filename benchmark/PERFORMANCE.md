# 架构优化性能对比

测试环境：Windows 10 x64，ZCode 3.9.1 / Electron 41 / Chromium 146，1440×900，DPR 1。  
原始数据：[`results-before.json`](./results-before.json)、[`results-after.json`](./results-after.json)。

## 最终保留策略

只保留有收益或不进入每键热路径的架构改动：

- 保留 `state.ts` 信号化和侧栏微任务批处理；
- 保留 `main.ts` 拆分及 `src/app/` 小型协调器；
- 保留 `pipeline.ts` 作为编辑管线组合根；
- 保留低频生命周期事件（打开、关闭、视图、设置）；
- **回退退化的每键通用事件总线**，改为显式依赖注入和同步直连：

```text
editor.ts
  -> pipeline.ts
      -> markdownModel.applyEdit
      -> virtualPreview.refresh
      -> outline.refresh（防抖）
      -> save.notifyDocumentEdited
```

这样仍然保持 Editor → Model → Preview 的单向数据流，但不承担 `bus.emit(doc:edited)`、订阅查找和 `bus.emit(model:changed)` 的固定开销。

## 同口径同步性能

| 场景 | 优化前中位数 | 最终中位数 | 变化 |
|---|---:|---:|---:|
| 冷初始化 | 12.9 ms | 5.2 ms | **-59.7%** |
| 中等文档普通打字 | 3.5 ms | 3.0 ms | **-14.3%** |
| 大文档普通打字 | 11.2 ms | 10.2 ms | **-8.9%** |
| 文档末尾追加 | 3.0 ms | 2.0 ms | **-33.3%** |
| 回车拆分段落 | 3.7 ms | 2.4 ms | **-35.1%** |
| 侧栏 20 次批量更新 | 36.1 ms | 0.4 ms | **-98.9%** |

最终保留版本在所有同口径同步场景中均没有退化。

## 已回退的退化方案

中间方案曾让每键编辑经过两次通用事件广播，测得：

- 中等文档普通打字：3.5 → 4.9 ms（+40.0%）
- 大文档普通打字：11.2 → 19.9 ms（+77.7%）
- 回车拆分：3.7 → 4.3 ms（+16.2%）

这些改动已经从生产热路径移除，不属于最终实现。

## 其他指标说明

优化前的打开文档、视图切换、滚动和 paint 场景包含真实 `requestAnimationFrame` 等待；自动化环境在后续运行中会暂停页面 rAF，因此最终 runner 只能清空微任务队列。两轮 wall-clock 口径不同，不对这些指标声称跨轮加速。报告只用同步、同口径指标决定是否保留改动。

## 结论

最终实现遵循“性能数据决定去留”：

- 信号批处理带来最大的确定收益，连续 20 次列表更新由 36.1 ms 降至 0.4 ms；
- 协调器拆分和同步管线没有破坏按键热路径；
- 通用事件总线只用于低频生命周期事件；
- 所有曾测得退化的每键事件广播均已回退。
